Why

Vibe coding is fast until you have to change it.

An agent that writes code nobody understands leaves you a project you cannot change safely. Sanoy keeps the speed and removes the blindness: a plan you approve, tests written first, a build that must pass before the agent finishes its turn, a second agent reviewing with fresh eyes, and a living document for every feature.

What you get

Guardrails that do not slow you down.

Install

Two minutes to the first feature.

  1. Install into any project, new or existing. Existing files are never overwritten. Add --stack dotnet, node, or python for stack-specific skills and permissions.

  2. Run /onboard in Claude Code. It learns the codebase, fills the profile and CLAUDE.md, writes the map, and adopts existing features.

  3. Check the setup with doctor. Later, update refreshes the skills without touching your config.

  4. Start. /feature for something new, /change for existing code, /status when you come back tomorrow.

Node 18 or newer, git, Claude Code 2.1 or newer. gh for GitHub pull requests and issues. No telemetry.

terminal
# any stack
$ npx sanoy-ai-workflow init

Questions

Before you try it

Does it work with my language or framework?

Yes. The core needs a build command, a test command, and git. Stack packs add conveniences (an EF Core migration skill for .NET, permission presets for Node and Python) and you can write your own in a folder.

Will it overwrite my CLAUDE.md or settings?

No. init keeps every existing file unless you pass --force, and update only refreshes the files the kit owns (skills, the reviewer, the hook). Your config, rules, features, and docs are yours.

How many questions will it ask me?

Few, on purpose. A question is asked only if the code cannot answer it, a wrong guess would be expensive to undo, and reasonable people would choose differently. Everything else is decided and listed as "decisions I made for you", so you overrule by reading, not by answering.

Does it send anything anywhere?

No telemetry, no network calls from the CLI or the hook. The only network use is what you configure: pushing to your remote, creating a pull request, or creating a work item in your own tracker.

What happens if the build breaks?

The Stop hook returns the error lines to Claude and blocks it from finishing until the build is green. If nothing relevant changed since the last green build, it does not build at all.

Can my team use it with other coding agents?

The state lives in files, so any agent that reads markdown can follow it. AGENTS.md points Codex, OpenCode, and Copilot at the same documents. The skills themselves are written for Claude Code.

Why "Sanoy"?

It is the author's first name, Yonas, spelled backwards. The workflow was extracted from his production project and generalized so anyone can use it.
